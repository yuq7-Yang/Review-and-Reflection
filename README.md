# Review and Reflection

周 / 月 / 年工作复盘技能包，适用于支持 Agent Skill 的 AI 助手环境（WorkBuddy、Claude Code 等）。

## 解决的问题

复盘最容易写成两样东西：流水账和表扬稿。前者只让人看到"很忙"，后者让人看不到问题。

这个技能做三件事：

1. **重建事实** — 从本机项目日志和文件痕迹里，还原这段时间实际做了什么，而不是靠回忆
2. **逼出结论** — 用对应周期的框架提问，把"做了什么"推到"哪里不行、下次怎么改"
3. **落成文档** — 输出一份自己会重读的东西，并结转下期要盯的事

## 三层框架的差别

同一个人的工作，周、月、年要看的东西完全不同。用同一套模板套三个周期，是最常见的失败。

| 周期 | 回答的问题 | 核心产出 |
|---|---|---|
| 周 | 这周哪里慢了，下周怎么快 | 卡点三段式（现象 / 根因 / 改法）+ 下周只做 3 件 |
| 月 | 时间去哪了，什么在重复 | 三类活占比 + 出现 ≥2 次的问题升级为机制问题 |
| 年 | 成了什么样的人，站在什么位置 | 能力矩阵（带证据）+ 最贵的三个教训 + 明年三个赌注 |

`references/` 里的示例统一用通用办公场景（方案文档、名单台账、文档审校、设计稿催办），不绑定任何行业。套用的时候，把示例换成自己岗位上的事即可，结构不用动。

## 目录结构

```
work-review/
├── SKILL.md                  # 主流程：定周期 → 扫素材 → 补盲区 → 归类 → 写稿 → 落文档 → 结转
├── references/
│   ├── weekly.md             # 周复盘框架与追问清单
│   ├── monthly.md            # 月复盘框架
│   └── yearly.md             # 年复盘框架
├── scripts/
│   └── scan_activity.py      # 扫描时间窗口内的日志与文件痕迹
└── tests/
    └── test_skill.py         # 自带 fixture 的自测，不依赖任何本机数据
```

## 安装

把 `work-review` 整个目录放进 skills 目录：

| 环境 | 路径 |
|---|---|
| WorkBuddy | `~/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` |

## 用法

直接说：

- 「复盘这周」
- 「做个月复盘」
- 「年终总结」
- 「回顾一下这个月做了什么」

技能会自动确定周期、扫描素材、追问盲区，然后成稿。

## 素材扫描

```bash
# 按周期（推荐，免去手算日期）
python work-review/scripts/scan_activity.py --period last-week --pretty

# 任意区间
python work-review/scripts/scan_activity.py --since 2026-10-05 --until 2026-10-11 --pretty
```

可选周期：`this-week` / `last-week` / `this-month` / `last-month` / `this-year` / `last-year`，返回的 `period` 字段（如 `2026-W45`）可直接用于命名文件。

周期为什么内置：`date -d "last monday"` 这类文本解析在部分环境会**静默给出错误日期**。实测 Git Bash 下 `date -d "2026-11-07 last monday"` 返回周六 11-07，既不是本周一也不是上周一，而且不报错。把日期算进脚本，用 `datetime` 处理，周一当天、月初、跨年周、闰年都测过。

脚本做了三层降噪，因为**文件数量不等于工作量**：

| 机制 | 判定 | 作用 |
|---|---|---|
| 例行产出识别 | 同一带日期的命名模式在窗口内重复 ≥4 次 | 排除 `ai-daily-2026-10-07.html` 这类自动化产物 |
| 素材堆折叠 | 同目录 ≥5 个文件且无成型交付物 | 一次爬虫抓的 800 张图，折叠成一条 |
| 交付物收紧 | 只认 `.docx/.pdf/.pptx/.xlsx` | `.md`/`.html` 会批量生成，不算交付 |

实测中，不做降噪时一个 38 天的窗口会算出 194 个"产出"，其中绝大部分是爬虫素材——统计完全失真。

## 测试

```bash
python work-review/tests/test_skill.py
```

55 项断言，自带 fixture（在临时目录造项目结构），clone 下来就能跑，不依赖任何本机数据。覆盖：边界输入、错误处理、日志筛选、例行识别、素材折叠、交付物口径、文档一致性、周期计算（周一/周日/月初/跨年/闰年）、性能。若本机存在 `~/WorkBuddy`，额外做一次真实环境冒烟测试，否则跳过。

## 前置条件

- 扫描脚本默认读 `<project>/.workbuddy/memory/YYYY-MM-DD.md` 结构（WorkBuddy 的项目日志约定）。其他环境需要改 `iter_memory_logs()` 的路径规则，或直接用日志文本喂给模型。
- 没有日志时，技能会退化成提问引导模式——这仍然可用，只是慢一些。
- 导出飞书文档是可选步骤，需要 `lark-cli`。不用飞书时，本地 Markdown 就是成品。

## 三条设计原则

写这个技能时，有三条是硬约束，改的时候别违背：

1. **日志不是事实全貌。** 会议、电话、当面沟通都不留痕。覆盖率不足时必须追问，宁可交一份标注"覆盖不足"的短复盘，也不用推测填补。
2. **不写表扬稿。** 每条结论必须挂靠具体事件：哪件事、涉及谁、什么结果、下次怎么改。
3. **返工和卡点是最高价值素材。** 顺的部分一句话带过，不顺的部分展开写。复盘的用处全在后者。
