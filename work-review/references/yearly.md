# 年复盘框架

## 定位

年复盘不再问"做了什么"，问的是 **"成了什么样的人、站在什么位置"**。

判断标准只有一条：一年后重读这份文档，能不能看出当时的判断哪里对、哪里错。看不出就白写。

```markdown
**最大收获**：…
**最大问题**：…

## 一、全年主线

按职能归并成 3–4 条，不按月份罗列。

### 1. 新业务方向从 0 到 1

- 判断：这是全年权重最高的一条，但也是最没有闭环的一条

### 2. 现有业务的标准化
…

### 3. 工具化（自动化、脚本、小程序）
…

每年主线超过 4 条，说明没有主线，只有杂事。

## 二、关键转折

哪几件事真正改变了你的位置或判断？只写 2–3 件，必须写清"之前怎么想 / 之后怎么想"。

| 事件 | 之前 | 之后 |
|---|---|---|
| 方案材料被否两次 | 以为内容做好就行 | 明白内部决策链比内容更花时间 |
| 审校任务返工两次 | 拿到活就开工 | 先确认交付形态再动手 |

没有转折就写"这一年基本是线性的"，不要硬凑。

## 三、能力矩阵

自评 1–5 分，**每项必须有证据**，没证据就留空（留空比虚高有价值）。

| 维度 | 分 | 证据 |
|---|---|---|
| 项目策划 | | 独立完成一个新方向的定位与方案材料 |
| 对接与协调 | | 建了联系人台账，但未验证转化 |
| 产品标准化 | | |
| 商务沟通与推动 | | 三次跨部门对齐，两次没推动 |
| 文档交付质量 | | 长文档审校 150+ 处问题、命中率 95% |
| 工具化 / 自动化 | | 例行自动化稳定运行半年，多个可复用脚本 |
| 行业理解 | | |

**短板判断**：（从留空的项里选一到两个，写清为什么空、明年补不补）

## 五、明年不该再由我做的事

| 事项 | 为什么不该再做 | 怎么甩掉 |
|---|---|---|
| 每日 AI 日报的手工兜底 | 已可完全自动化 | 加失败告警，不再人工看 |

## 六、明年三个赌注

押什么，同时明确**不押什么**。

| 赌注 | 为什么押 | 一年后的验收信号 |
|---|---|---|
| 项目策划能力做到能独立提案 | 这是岗位主线，权重最高 | 能独立出一份被采纳的方案 |
| 数据分析能力（台账 → 结论） | 现在只有台账没有结论 | 能从数据里说清结论 |

**明确不押**：不押纯技术路线（写更复杂的脚本），工具只作为提效手段。

三个赌注够了。押五个等于没有重点。
```

## 写作顺序

先写第四、五、六节（教训、边界、赌注），再回头写前面。因为前三节容易写成成就展，而后三节才是这份文档的价值所在。

## 关键判断

1. **这一年有没有产生"只有你能做"的事？** 没有的话，说明还在可替换的位置上。
2. **涨的是能力，还是熟练度？** 同一件事做第十遍更快了，那是熟练；能做原来做不了的事，才是能力。
3. **消耗清单是不是空的？** 空的话，说明明年大概率重复今年。
4. **三个赌注之间有没有冲突？** 有冲突就要砍掉一个。

## 篇幅

正文 2000 字以内。年度复盘写长很常见，但超过这个长度通常是在叙述过程而不是下判断。
